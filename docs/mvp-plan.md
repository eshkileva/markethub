# MarketHub — план MVP

Рабочий документ. Каждый следующий слайс берём **сверху списка «Осталось»**. Слайс не закрыт, пока нет typecheck + smoke + e2e.

**Продукт:** C2C-маркетплейс для BY / RU / KZ. Один аккаунт, объявления в разных странах, цены с конвертацией, доверие к продавцу.

**Стек:** `apps/web` React + Vite + TanStack Router/Query + Zustand + Tailwind. `apps/api` Fastify + Drizzle + PostgreSQL. `packages/shared` схемы и домен. Redis, MinIO, in-process events.

---

## Границы MVP

### Входит

Полный цикл без денег: регистрация → объявление → каталог → чат → бронь/продажа → отзыв → жалоба → модерация.

### Не входит (не делать, пока явно не попросим)

- Платежи, эскроу, комиссии, доставка как сервис
- OAuth Google / VK / Telegram (таблица `auth_identities` уже готова — после MVP)
- Почта: подтверждение email, сброс пароля, SMS/телефон
- Премодерация объявлений (`pending_moderation` в схеме есть — не включать)
- Карты, геокодинг, полнотекст / Elasticsearch
- RabbitMQ outbox, отдельный админ-CMS категорий
- Мультиязычность (UI только RU)
- Нативные приложения

## Как пишем код

Это не отдельный слайс «потом отрефакторить». Каждый слайс сразу в этом стиле. Если трогаем жирный файл — выносим заодно, не размазываем новую логику.

1. **Слои**
   - API: `http` (тонкий роут) → `application` (правила) → `infrastructure` (SQL). В роуте нет бизнес-веток и сырого Drizzle, кроме простых GET.
   - Web: `pages` (экран) → `features` (действие) → `entities` (карточка, тип) → `widgets` (shell) → `shared` (api, ui). Роут-файл только клеит page.
2. **Один смысл — один файл.** Хук, маппер ошибок, константы статусов, тип ответа API не живут внутри JSX на 400 строк.
3. **Без лишнего.** Нет абстракций «на будущее», нет копипасты «на всякий случай», нет второго способа сделать то же самое. Повторилось дважды — вынести.
4. **Общее — в shared / entities.** Статусы объявлений, `formatMoney`, схемы Zod, тексты ошибок API → UI.
5. **Имена.** Понятные, без сокращений вроде `tmp`, `data2`, `handleClick1`.
6. **UI.** Токены из `design-system/MASTER.md`. `MASTER.md` не регенерировать. Lucide, без эмодзи. RU-копирайт.
7. **Каденция.** Один слайс → typecheck `api`+`web` → smoke API → e2e. Следующий слайс только после зелёного.

## Критерий «MVP готов»

Можно провести сценарий на чистом `pnpm dev`:

1. Два пользователя регистрируются.
2. Продавец публикует объявление с фото и характеристиками; оно в каталоге и на главной.
3. Покупатель находит через поиск/фильтр, пишет в чат, добавляет в избранное.
4. Продавец бронирует → объявление пропадает из каталога; затем отмечает проданым.
5. Покупатель видит сделку в **Покупках**, оставляет отзыв, Trust Score обновляется.
6. Покупатель жалуется на другое объявление; модератор скрывает его.
7. Оба видят уведомления; непрочитанные чаты видны в сайдбаре.
8. Профиль, настройки, свои объявления, продажи — без заглушек.

Когда пункты 1–10 закрыты и сценарий проходит — MVP по продукту готов. Дальше только то, что попросите отдельно (OAuth, почта, платежи).
